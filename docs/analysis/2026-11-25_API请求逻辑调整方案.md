# 当前 API 请求逻辑调整方案（对齐 hongguo-android）

> 关联分析：[hongguo-android API 与鉴权加密分析](2026-11-25_hongguo-android-API与鉴权加密分析.md)。
> 本文只给**方案与验证口径**，未改动应用代码；优先级 P0=协议健壮性、P1=能力对齐、P2=可选增强。

## 1. 目标与非目标

**目标**：在保持 Flutter 端「签名字节级一致、纯 Dart 本地闭环、六端可用」的前提下，补齐 Android 参考实现已经验证过的协议路径与错误语义，提升取址成功率与后续接账号的可扩展性。

**非目标**：
- 不在本轮引入云端账号登录、Cookie 注入 UI、批量云写回或进度自动上传；
- 不改动 `PureSign` 六头算法本身（签名头顺序、query 编码、body 字节）；
- 不以 Android 的实测结论直接覆盖 Flutter 的实测结论——设备身份复用等冲突项先做 A/B；
- 不把探测脚本、诊断输出或本文写成线上验收证明。

## 4. P0：先做协议健壮性

### 4.1 详情取源顺序做成策略，不改默认行为

- 在 `AppSettings` 增加 `detailSourceOrder`（`webFirst` / `appFirst`），默认 `webFirst` 保住当前缓存快照与 191 项红果测试行为。
- 把 `CatalogClient._detail` 里的官网竞速与 App 分集请求拆成两个私有方法 `webDetailRace(id)` / `appDetail(id)`，按策略编排；两条路径共用同一个 `_details` 缓存入口，缓存键加策略后缀，避免切换策略后读到旧顺序的结果。
- 错误聚合仍保留三层结论：采用 appFirst 时若 App 失败但官网成功，日志/诊断记录 App 的错误类型与官网命中，不把失败伪装成成功。
- 验证：`packages/api/test/catalog_test.dart` 增加两种顺序各一组（官网胜出、App 胜出、两层皆失败）；`./tool/verify_all.sh` 全绿后再考虑把默认值切到 `appFirst`。

### 4.2 播放路由抽象 + 补齐缺失路由

在 `packages/api/lib/src/video_model_client.dart` 内新增一个内部 `PlaybackRoute` 描述（`id / method / host / path / bodyFactory / identityPolicy`），把现有三层改写为有序列表，再按 Android 顺序补：

| 顺序 | 路由 | 备注 |
|---|---|---|
| 1 | 官网公开 fallback + player ld+json（现状） | `best/auto` 且 `preferApp=false` 时优先；保持明文 MP4 语义 |
| 2 | v5 `video_tab/multi_video_model/v1/`（无正文 GET） | 新；需 Kotlin `Signer` 等价实现（branch==0） |
| 3 | v5 `novel/player/multi_video_model/player/v1`（gzip 正文 POST） | 新；需 v5 常量 + gzip body + branch==0 签名，最多 2 次 |
| 4 | 旧 `novel/player/video_model/v1/`（POST，`version_code=73532`） | 新；需 `PlayerSign` 等价实现 |
| 5 | App `multi_video_model/v1/`（POST，六头签名，现状） | 保留现状请求字节，不动 `branch==0` 抖动逻辑 |
| 6 | 同 5 换 `api5-normal-hl.fqnovel.com` | 新；只在空响应/5xx 时换主机，签名按新 URL 重算 |
| 7 | 旧 `preload/v1`（免签） | 现状兜底，保持最后 |
| 8 | 官网匿名公开取址（`seriesId` 可用时） | 新；仅在前面都失败时启用 |

约束：
- **URL、body、headers 必须一起冻结**（`VideoRequest` 已有此语义）；换主机或改 query 后必须重签，不得复用旧签名。
- 新增 v5 / 老单集路由前，先在 `hongguo_core` 落下独立的签名器（v5 用 `Signer.kt` 的 12 组固定向量做对拍，老单集用 `PlayerSign` 语义），**不要把这些请求塞进现有 `PureSign`**。
- 匿名注册后可补一次 `GET /service/2/app_alert_check/` 激活并保留响应的 `klink_egdi` 供 v5 query 使用；激活失败只记诊断、不阻断取流，且不落盘 device_token。
- 每条路由失败要写入 `sources` 诊断清单；最终错误保留第一条可重试/终止语义，不压平成同一种异常。
- 总预算沿用 20 秒；单路由 8 秒；换主机不得突破预算。
- 验证：新增离线路由矩阵测试（每条路由的空响应/HTTP 500/有模型三种）；`probe_playback_sign.dart` / `probe_identity.dart` 只输出摘要，不打印签名头。

### 4.3 设备身份策略 A/B，而不是直接切换

- 抽出 `PlaybackIdentityPolicy`：`freshPerAsk`（Flutter 现状，也是 Android `PlaybackDevice.java` v5 路径的策略）与 `reuseOnSuccess`（Android `AppSource` 路径）。默认仍是 `freshPerAsk`。
- 复用策略只在**该身份成功返回过视频模型**后生效；空响应、401/403、业务拒绝立即丢弃并重注册；并发只共享在途注册，不共享已消费身份。
- 用 `packages/api/tool/probe_identity.dart` 做两次只读对照：同一身份连续两次取址的返回形态、拒绝窗口；记录成功率与耗时，不记录 Cookie/设备 ID 原文。
- 只有复用策略在真网上稳定优于现状，才通过 `AppSettings` 开放开关；否则保留现状并在文档里写明两条 Android 路径策略不同及其原因（播放器 UA/版本模板、路由不同）。

### 4.4 错误分类与“不重放”边界

新增一层轻量分类（可放在 `network_retry.dart` 或新的 `upstream_failure.dart`）：

```text
UpstreamFailure
├─ TransportFailure    (timeout / connection / 5xx / 429) → 可重试，尊重 Retry-After
├─ EmptyEnvelope       (HTTP 200 + 空/截断 body)         → 有界重试
├─ RiskControlFailure  (429/110001/110002/110003 或关键词)→ 不重放，退避提示
├─ AuthExpiredFailure  (401/403/8/1001 或关键词)         → 不重放，清会话，提示重新验证
└─ BusinessFailure     (其它 code != 0)                  → 不重放，按码呈现
```

- 现有 `IncompleteCatalogResponse` / `PlaybackUnavailable` 保留为对外兼容类型，内部映射到上述分类，避免一次性改动所有 UI 分支。
- 风控关键词表沿用 Android：`verify / captcha / risk / 频繁 / 稍后 / 验证 / rate limit / too many`；鉴权关键词：`token / 登录 / login / 未登录 / not login / unauthor`。
- 所有写操作（收藏、预约、进度、未来的账号写入）只允许提交一次，成功后必须回读，不因超时自动重放。
- 验证：`network_retry_test.dart` 补各类码的“是否重放”断言；探测脚本不得把账号字段写入日志。

## 5. P1：能力对齐与可维护性

### 5.1 账号协议预留（不启用）

- 先只做**只读领域模型与存储边界**：`AccountCredentials`（官网 Cookie / App 设备 Cookie 分属两个字段）、不透明字符串 `bizUserId`、`agw` 网关信号、账号代次（generation）。
- 存储沿用 `SystemSessionVault`，但按账号代次命名空间隔离；退出/切换后旧代次的在途请求不得写回。
- 签名器若实现账号分支，必须独立配置：`branch==0`、`passport-sdk-version=50561`、`x-tt-request-tag=t=0;n=0`、POST 带 `x-vc-bdturing-sdk-version`，不与内容层 `PureSign` 混用。
- 本轮不接登录 UI、不发起短信、不读云片单、不上传进度；仅在文档中登记接口清单与验收边界。

### 5.2 缓存治理

- 给 `_info`（track TTL 3 分钟）与 `_details`（6 小时）补定时清扫或访问时清扫 + 近似字节上限，防止长会话单调增长。
- 统一“空响应不写缓存”：当前 `fetchVideoInfo` 只在成功后写入，`PlaybackUnavailable` 删除旧条目；新增路由后要保持同一规则。
- 图/列表快照继续保留 `library-cache.json`，不改动 DB-first 设计。

### 5.3 配置与观测

- `AppSettings.protocolJson()` 增加新开关（`detailSourceOrder`、`identityPolicy`、`playbackRouteSet`）并兼容老 JSON 缺字段回退。
- 诊断输出只含路由 ID、状态码、耗时、错误分类与摘要字段；禁止输出签名头、Cookie、URL 原文、`key_seed`。
- 在 `docs/project-map.md` / `docs/README.md` 增补本文与 Android 分析文档入口。

- 账号相关行为按 [ACCOUNT_INTEGRATION.md:63-67](../../references/hongguo-android/docs/ACCOUNT_INTEGRATION.md#L63-L67) 由本人账号最终验收，不能用 HTTP 200 代替登录/同步成功。
