# 我的：收藏、历史与缓存观看

## 导航与平台布局

主导航改为“发现 / 分类 / 我的”；设置页迁入“我的”右上角齿轮。TV 保留已有本地缓存快捷项，并将设置项改为“我的”。不增加虚构登录状态。

| Before | After | Why |
| --- | --- | --- |
| 设置占据主导航 | 我的聚合收藏、历史和本地缓存 | 主导航优先承载观看任务 |
| 个人内容散在配置中 | 顶部三个入口和列表，右上角设置 | 内容与配置分层 |
| 只有缓存连续播放 | 自动保存观看集数、位置，可点击历史续播 | 找回上次的观看位置 |

手机：底部“我的”，顶部设置，三等宽快捷入口，纵向列表；下拉刷新本地数据。PC：沿用侧栏/导航轨，内容区最大宽度 1000，保留鼠标悬停提示和键盘标准焦点。横屏小窗口列表可滚动，顶部设置保持可达。TV 使用原有遥控器导航环境，操作均为可聚焦按钮或 ListTile；不新增只依赖滑动的操作。

参考 [YouTube You tab](https://support.google.com/youtube/answer/9209643?hl=en-GB) 和 [My Netflix](https://about.netflix.com/en/news/introducing-my-netflix-a-one-stop-shop-for-series-and-movies-you-want-to) 的内容聚合思路；本页不复刻其账号、推荐和云同步能力。

## 收藏与历史

详情页与播放器选集面板提供爱心收藏；同一剧目仅保留一个收藏，可在“我的”取消。观看历史按剧目归并，只记录最近一次播放的 vid、集号、进度、时长、时间、本地/在线来源和画质。不因只打开详情页而产生观看记录。

实际播放成功后记录；播放中最多每 10 秒提交一次，暂停、切集、进入后台与退出时补存。异常被系统强制结束可能丢失最后约 10 秒进度。按记录时间降序展示。已到结尾的记录点击后从本集开头重看；其他记录恢复保存的位置，不自动跳到下一集。

在线历史优先使用已有剧集元数据，否则请求详情；通过 vid 匹配分集，分集失效报错，不按过期数组下标播放其他集。本地历史重新校验实际缓存并复用本地队列，缓存不存在时报错，绝不转成在线下载。缓存入口仍采用已有按剧目归组的离线列表及连续播放逻辑。

支持移除单条历史、二次确认清空历史。清空历史不删除收藏或视频文件，清理视频不删除收藏与历史。设置内原有缓存维护入口继续保留。

## 数据方案

原生五端在应用支持目录写入独立 `personal-library.json`（schema version 1），复用 FilePreferencesBackend 的临时文件写入与原子替换；所有更改串行，写入成功才更新内存与通知 UI，失败保留上一版。读取失败/未知版本阻止覆盖并提供重试。无签名、会话、视频源 URL 或密钥入库。

历史上限 500 部，按最后观看时间保留；收藏上限 2000 部，到限拒绝新增而不悄悄删除已有收藏。按剧目主键查找和顺序列表即可满足本轮，不引入 SQLite 五端 FFI/原生依赖。未来需要海量分集历史、复杂筛选或事务查询时，可在 PersonalLibrary 接口内迁移 SQLite 并增加版本迁移。Web/不提供存储的测试 runtime 使用进程内会话记录，不宣称浏览器刷新后持久化。

`MaterialApp` 的 Android 全局默认 flavor 已移除，以免 macOS/iOS 被要求存在 mobile scheme；Android 命令应显式使用 `--flavor mobile` 或 `--flavor tv`，现有移动验证脚本和 Action 已显式指定。

## 实现入口

- `lib/personal/personal_library.dart`：模型、持久化队列、收藏和历史管理。
- `lib/features/my_page.dart`：聚合、删除、缓存入口和续播。
- `lib/personal/favorite_button.dart`：详情与播放器共用的收藏按钮。
- `lib/features/player_page.dart`：采样、关键生命周期补存、initialOffset 续播。
- `lib/platform/runtime_native.dart`：原生存储目录及运行时生命周期。

验证日志位于 `docs/evidence/my-library/`；自动化布局检查不等于所有原生平台已目视验收。

## 本轮验证结果

- 应用层 81 项通过，1 项 TV 构建专用用例在非 TV 构建中按条件跳过。
- 个人存储及“我的”布局 7 项通过：手机、桌面、矮横屏；收藏增删、独立清理、写失败回滚、版本读取失败重试及短视频完成判断。
- macOS 原生与 Android 真机各 1 项通过：第 2 集从 700ms 起播，实际进度分别观察到约 916ms 和 833ms，暂停后写入文件，重新打开个人数据仍可读取历史及收藏。原生用例是确定性本地视频，不请求在线内容服务。
- 应用静态检查通过。iOS 本轮未执行原生验证；TV 未进行本功能的遥控器原生验收。

历史最后位置以播放器异步实际进度为准，原生通过 Media.start 在加载时设置起播点，避免 open 后立即 seek 的时序竞争。
