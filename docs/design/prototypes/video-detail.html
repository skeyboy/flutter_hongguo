这一页是被推入的一页，不是一个地址。发现 / 分类 / 榜单里的卡片点进来 = pushAppPage(AppScreen.detail)，转场 slidePageTransitions（新页从右进、旧页左移 0.3）； 左上「返回」只有一个语义：pop，列表页保活原位。原型之间用 ?g=&i= 传「进来的那部剧」， 那是调试入口，不是产品能力——App 没有 URL，也不写 ?ep= 去「分享某一集」。
版面按 宽度 × 输入族 分派，宽屏不产生第二种布局：整个正文是 Center + ConstrainedBox(maxWidth:960) 的一条单列（detail_page.dart:140-143）； <720 选集 rows:3 / cellExtent:100，≥720 只是 4 行 × 120 并把缓存弹层从底部抽屉换成居中对话框。 上一版的 330px 右侧标签栏（选集 / 接下来播放 / 缓存）删了：客户端没有它，「宽屏 = 两栏」也是网页栅格思路。
点任意一集 = push 播放页。旧版把它画成同一页 classList.toggle('playing') + scrollIntoView，那是 SPA 页内状态；真实代码走 detail_page.dart:125-138 的路由推入， pop 回来才刷新「上次看到第 X 集」与主按钮文案。
推荐块为什么只有一块、名字还这么短：上游没有 related / recommend / 相似 端点， 唯一能自证的关联是把这部剧自己的面板词 cate_ id 放进 select_items 再要一页； 块名只能是「同题材 · 那个词」，一个词都对不上时退到「平台热门」（sort=hot_score）， 无命中 / 失败 / 空页则整块不出现。related_dramas.dart:6-12 的类型里刻意不带 最新/热度 标记， 所以这里也不画分数角标——切到「后妈难当」看整块缺席的状态。
