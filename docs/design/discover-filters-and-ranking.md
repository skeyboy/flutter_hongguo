榜单的真实接口形状（现读 `packages/api/lib/src/catalog.dart`）：

- `RankCatalogRepository.rank({board='recommend', cursor})`（`:166-168`）——**没有 genre、没有 theme、没有周期**。
- 实现 `_rank`（`:506-550`）把参数钉死成一条 cell：`cell_id=7470092475068071998`、`tab_type=26`、`selected_items=comic_series_rank`、`sub_selected_items ∈ {comic_series_hot_rank, comic_series_hot_play, comic_series_new_rank}`（`:510-529`）。**这块 cell 自己发布的其实是 5 条赛道 × 25–27 块榜**（`cell_selector.outer_row` 原文；四次取样的并集是 27，块数每次略有出入，见证据 README §3），app 只接了其中 3 块。
- 前端配合写死 `_boardGenre='comic_series'`（`library_page.dart:44`）与 `_boardNames={推荐榜, 热播榜, 新剧榜}`（`:45`），注释里已经承认「榜名进标题是诚实版本的做法」。
- 卡片能显示的东西由模型决定：`Drama` 只有 `id/title/cover/intro/episodeCount/tagNames`（`catalog.dart:81-129`）。**位次只能靠数组下标**（上游不返回名次字段，本来就该这么用）；**热度、收藏、评分、徽标、占位主色上游都给了、模型一个都没留**（`rec_text_item.RecommendText`=「997万推荐」、`secondary_info_list[i].content`=「422.8万收藏」、`score`=「8.2」、`tag_info.text`=「爆剧/新剧」、`color_dominate`=`#282828`；实测清单见证据 README §4）；**只有趋势确实没有**——字段位 `rec_arrow_type` 存在，四次取样 30 张卡全为 0，语义未证实。
- 同一批取样还量出两个必须写进界面的坑：① `play_cnt` 与 `rec_text_item` 不是一个口径（热播榜第 3/4 名 `play_cnt` 只有 1035/984，而热度文案写 6182万/6038万，差四个数量级 → 一张卡上只许说一个「热度」）；② `rank_version` 只给两块榜（推荐空白、其余给 epoch 秒，实测为整分钟且滞后取样时刻 0–4 分钟 → 能写「更新于 10:04」，不能写「实时」）。

发现页的筛选词表同理——**不是上游缺能力**：`landpage/v` 的 `selector_rows` 按类型发布 **7–9 个维度**（真人剧 7 维：29 主题 / 42 设定 / 11 背景；漫剧 9 维，独有加 全部画风(3) 与 全部状态(2)；AI 剧 7 维），而 `_themes()`（`catalog.dart:470-504`）命中主题那一行就 `return`，其余行连同 `row_name`、`selection_type` 一起丢；`_selection()`（`:409-421`）总共只组 7 个键，设定/背景/受众/时间四个键**发了但恒送空数组**，画风/状态两个键**根本没发**（全仓 `grep -rn "art_style\|creation_status" packages/api/lib packages/app/lib` 零命中）。

词表还**按次不稳定**：同一分钟内四次独立取样，真人剧 2/4 次拿到、漫剧 2/4、AI 剧 3/4，其中一次三张面板全缺（形态统一：上游 HTTP 200 + 空 body → `IncompleteCatalogResponse`）。同四次里榜单全部全通。所以筛选行必须允许整行不出现，而榜模块不能因为取词表失败而跟着空。

## 2. 由此来的五个具体矛盾（这是要解决的清单）

1. **一行两义**：同一行里，左半改「这一页请求什么」（排序/接口），右半改「看哪一页」（类型）。两者视觉权重完全相同（同一套 `ChoiceChip`），但一个是参数、一个是路由，交互后果差一个数量级（类型会重置题材）。
2. **开榜就拆掉别人的控件**：`isRanking(pane)` 时类型行整个消失（`:1887` 的条件），因为 `rank(board)` 不吃 genre——代码注释自己的判断标准是「一个改了什么都不变的行是假控件」。代价是用户在榜上时看不到「我原来站在哪个类型」。
3. **同一个位子放两种完全不同的东西**：第二行平时是「这个类型下的题材」（下钻），榜单时是「换一块榜」（并列切换）。控件位共享、语义相反（一个收窄、一个换集合），保活 key 也要靠 `board:` 前缀硬分（`:210-225`）。
4. **名字承诺了接口没做的范围**：三块榜都叫通用名（推荐榜/热播榜/新剧榜），实际全部是 `comic_series_*`（漫剧域）。用户从「短剧」页进榜，看到的是漫剧榜，而类型行已经消失，没有任何地方说明这件事。
5. **榜不像榜**：没有位次标识、没有热度、没有趋势、没有更新口径，渲染路径和普通网格是同一条（同一个 `_level2Page` 网格 → `DramaCard`），所以「榜」目前只是一个换了参数的列表。

顺带的现状事实：`view` 的改动**不会**写 genre/theme（`:1510-1524`），所以退榜后类型/题材选择仍在——这条要保住，它是「榜单是模式」这个设计的唯一好处。

## 3. 主流产品怎么分层（对照，带来源）

- **形态 A｜一级 Tab + 二级 chip 行 + 排序**（红果、腾讯视频、爱奇艺）：顶部固定导航，进入频道后用题材/地域/年份收窄，排序（最热/最新/最高热度/最高收藏）与筛选并列；筛选条在触发后吸到导航下方。规律是 tab 超过 5 个就横滑或收进「更多」，适合触屏、代价是纵向空间。来源：[红果频道切换](https://m.php.cn/faq/2137948.html)、[红果快速找剧](https://k.sina.cn/article_7879996480_1d5af344006801ylh4.html)、[内容筛选功能规律](https://zhuanlan.zhihu.com/p/66081142)、[筛选页设计总结（点名腾讯/爱奇艺顶部显示式）](https://m.zcool.com.cn/article/ZMTA2Mzk0OA==.html)。
- **形态 B｜维度收进漏斗/抽屉**（红果的漏斗按钮、B 站分区、YouTube 网页的「筛选」对话框）：列表区干净、能承载多维组合，代价是入口深一层且必须回显已选条件。来源：[B 站分区的二级抽屉](https://www.cnblogs.com/moranjl/articles/16469542.html)、[YouTube 网页筛选=搜索页对话框](https://pmc.ncbi.nlm.nih.gov/articles/PMC9465614/)。
- **形态 C｜侧栏承载一级**（腾讯视频 PC 全部频道在左 rail，可增删与拖拽排序；快手是「顶部页签 + 左侧抽屉」的少数派）：适合鼠标，窄屏不适用。来源：[腾讯视频 PC 频道管理](https://jingyan.baidu.com/article/c33e3f482469d2ea15cbb51a.html)、[快手结构分析](https://www.woshipm.com/evaluating/1748301.html)。
- **榜单做成独立模块的公共规则**（抖音热榜、微博热搜、猫眼、Netflix Top 10、短剧行业榜）：① 入口通常**多处**（抖音热榜主入口在搜索页、发现页下拉给快捷入口；Netflix 把每日 Top 10 做成首页一条带徽章的行，另有独立站点）；② 榜内是**两层并列切换**（赛道 × 周期；他们的周期是接口给的，本仓上游没给，所以这里只能落成「赛道 × 榜单」，见 §4），抖音短剧榜分红播/甜剧/都市等赛道，猫眼按类型→平台三级、支持任意历史日期快照；③ 榜项三要素是**位次 + 热度值 + 趋势/标识（新/飙升/热/爆）**，微博公开了热度公式与每分钟更新、抖音短剧榜每日更新统计前一日展示前 30；④ **更新口径必须写在页面上**，Netflix 把周更改成 24 小时后参与提升是公开实测结论；⑤ 短剧行业侧（DataEye 热力榜、WETRUE）就是「日/周/月 + 新剧入榜数 + 题材标签」范式。来源：[抖音热榜入口与标识](https://m.php.cn/faq/3070714.html)、[微博热搜规则](https://m.s.weibo.com/hot/description?ua=iPhone12,1__weibo__12.9.0__iphone__os15.6.1)、[猫眼榜单三级与历史榜](http://m.php.cn/faq/2989891.html)、[Netflix 官方 Top 10](https://about.netflix.com/zh_cn/news/see-whats-popular-on-netflix)、[Netflix 改 24 小时更新的实测](https://www.vulture.com/article/netflix-top-ten-most-popular-explained.html)、[抖音短剧榜赛道与口径](http://lmtw.com/mzw/content/detail/id/244070/keyword_id/-1)、[DataEye 热力榜](https://www.toutiao.com/article/7324569348595794432/?wid=1710383236017)。
- **未取到公开证据**：腾讯视频/爱奇艺站内榜单与分类筛选是否共享选中状态；小米电视影视聚合的具体实现。设计里凡押在这两点上的部分，都按「不依赖它」处理。
- **TV 不复用滑动模型**：Android TV 明确 D-pad 四向、同时只有一个焦点；Apple tvOS 用焦点放大 + Top Shelf 承载热门推荐而不是塞筛选。来源：[Android TV 焦点系统](https://developer.android.google.cn/design/ui/tv/guides/styles/focus-system?hl=zh-cn)、[Apple HIG 遥控器](https://developer.apple.com/cn/design/human-interface-guidelines/remotes)。本仓 TV 已是独立页（`tv_library_page.dart`），本轮不动它。

## 4. 设计：一层一义，把榜单从「模式」升成「目的地」

**核心决定**：榜单从 `view` 里的一个 chip 拆出来，成为与 发现 / 分类 并列的 **L0 目的地**；发现页第一行只剩「类型」，排序与模式归到第三层。理由按代码自己的标准说：`rank(board)` 不吃 genre/theme，它塞在发现页里就必须拆掉别人的控件（矛盾 2），放在目的地层则一行都不用消失；且它现在实际是漫剧专属（矛盾 4），并列在类型行旁边是在暗示「这是当前类型的榜」。

新分层（每层只有一个职责；维度不是前端编的，是 `landpage/v` 的 `selector_rows` 按类型发布的原名与原 id）：

```
L0  目的地   发现 · 分类 · 榜单 · 我的      （换页；榜单在这里，不在 chip 行里）
L1  类型     真人剧 / 漫剧 / AI 剧          （换页；上游 row「全部体裁」，仍会重置 L2 —— 保留现状语义）
L2  主题     该类型下的主题                 （吸顶第二行，横滑下钻；上游 row「全部主题」，cate_*）
L2′ 更多筛选 设定 / 背景 / 受众 / 时间 /（漫剧加 画风 / 状态）（只改请求不换页；上游给几维画几维）
L3  排序     最新上架 / 最高热度 / 最高收藏  （只改请求不换页；上游 row「全部推荐」实测就这三档）
```

三条由实测改掉的旧假设：

1. **排序没有第四档**：app 现在的「推荐」不对应任何 `sort` 值（`catalog.dart:430` 的白名单只有 `online_time/hot_score/hot_collect`，与上游 `全部推荐` 行的三个 id 一字不差）。实施时「推荐」要么折回「最新上架」，要么作为一个不带 sort 的默认态存在，不能假装它是第四种请求。
2. **L2′ 才是这次真正能扩的层**：除主题外的 4–6 个维度上游一直在发，app 已经在发键但送空数组（§1 末）；它们的 `selection_type` 由上游给，**多选/单选不用前端猜**。
3. **维度集合按类型不同**：画风与状态只在漫剧出现 → 不能画一张固定表单，只能「上游给几行画几行、缺的行整行不出现」；又因为词表按次缺席（同一分钟四次取样有 1 次三张面板全空），缺行必须是常态分支而不是异常分支。

榜单模块内部自成两层并列，不借用 L1/L2（`rank` 请求不吃 genre/theme 已实测）：

```
L0′ 赛道 = cell_selector 发布的 selected_items：全部(9) · 漫剧(4) · 真人剧(6) · AI剧(6) · 演员(2)  ← 括号是四次并集的榜块数；单跑实测 25–27，条数必须现读不能写死
L1′ 榜单 = 该赛道 items[] 的 show_name + selector_item_id；换榜单不换赛道，只改 sub_selected_items
榜卡     位次（1–3 金银铜大字，来自数组下标）+ 封面（可用 color_dominate 占位主色）+ 标题
        + 评分（score）+ 题材·集数（sub_title，如「玄幻·全1000集」）+ 徽标（tag_info.text = 爆剧/新剧）
        + 热度（rec_text_item.RecommendText）+ 收藏（secondary_info_list[i].content）
        +〔趋势〕——字段位 rec_arrow_type 四次全 0、语义未证实，画虚线占位不画假箭头
口径     「更新于 HH:MM」仅当 rank_version 非空（实测推荐榜为空串、热播/新剧给整分钟 epoch）
缺省     某赛道这一次没返回子榜（实测 live-sample 那次的演员赛道整个 sub_cell_selector 缺失）→ 这一枚不画，而不是画一个空 tab
        演员赛道的两块（剧星榜/星光榜）条目不是剧 → 本轮不接，界面与 RankEntry 都先按剧建模（证据 README §3）
```

**周期这一维上游确实没有**：`cell_selector.inner_rows` 四次取样都是空数组。所以原设计的 `L1′ 周期 日/周/月` 整条删掉——不是暂缓，是这条需求在现接口上不成立（证据 README §3）。要日/周/月只能等上游另发 cell 或赛道。

发现页仍保留一条**榜单入口卡**（横滚，前 3 名 + 「全部榜单 ›」）：这是主流的「首页一条榜 + 独立页」双入口做法（Netflix、抖音都这样），用来抵掉「榜单升为目的地后入口变深」的代价。入口卡上的热度文案就用 `rec_text_item`（实测「9388万热度 / 6190万热度 / 6182万热度」），**这是发现页唯一一处允许出现榜单内容的地方**，它不吃 L1/L2 的选中值，所以点它是换目的地而不是换筛选。

保住的现状语义（都是已发版验证过的，不能顺手改掉）：切换目的地/类型不重置别的 pane 的 feed 保活；`board`/题材改动只重挂自己那条 feed；顶段可折叠、两行筛选常驻；触屏第一次点按只显形不暂停之类与本页无关但同理。

## 5. 榜单模块的边界（拆分怎么落，本轮不实施）

| 面 | 落点 | 职责 |
| --- | --- | --- |
| 接口 | `packages/api/lib/src/ranking.dart`（新，从 `catalog.dart` 拆出 `RankCatalogRepository`） | `rank({track, board, cursor})` → `RankPage{entries, nextCursor, updatedAt?, tracks}`；`RankEntry{drama, position, heat?, collect?, score?, badge?, subtitle?, dominateColor?, trend?, reason?}` ——除 `trend/reason` 外全部有实测字段位（证据 README §4），`trend` 只能是 null 并在文档里标「上游有字段位、语义未证实」；`updatedAt` 来自 `rank_version`，推荐榜为空 → 类型上必须是可空 |
| 编排 | `packages/app/lib/ranking/ranking_controller.dart` | **赛道×榜单**的保活（键 = `track|board`；原设计的 `board|period` 作废，上游没有周期维），**不复用** `_ThemeFeed`（它的键含 genre/theme，语义不同）；`tracks` 从 `cell_selector` 现读，禁止再写死 3 个 board 名 |

## 6. 平台分派（PC / mobile / TV 各自按输入族，不给一套文案两边用）

**移动/触控（compact < 720 与中间宽度）**

- L0 目的地：底部 `NavigationBar`（现状）加「榜单」项，或顶部 tab——原型给的是顶部 tab，因为底部已经 4 项、加到 5 项后「我的」和「榜单」挤在一起；这条留给预览时定。
- L1/L2 两行吸顶保留（v0.3.12 已实测折叠不再带走筛选）；行内溢出走**横向滑动**（触控族的自然手势），行尾固定两枚：`≡`（L2′ 多维抽屉）与 `排序 · 最新上架 ▾`（L3）。主题行实测最多 42 项（真人剧的「设定」行），横滑是必须的而不是可选。
- L3 排序：放在第二行**尾部**一枚 `排序 · 最新上架 ▾`，点开的底部弹层只列**三项**（上游 `全部推荐` 行实测就 `最新上架/最高热度/最高收藏` 三档；app 现有「推荐」不对应任何一个 sort 值，实施时折回默认态而不是当第四档）。触屏措辞跟现有先例走「点按/滑动」，不写键盘提示。

**桌面/鼠标（wide ≥ 1100 与中间窗口）**

- L0 目的地：左侧 rail（现状 `:2426`）加「榜单」，点击零动画直达（v0.3.13 已经这么做了）。
- L1 类型放顶部，L2 主题第二行；两行都溢出为「更多 ▾」下拉而不是横滑——鼠标横向拖拽翻页已被明确禁掉（`desktopHost` 不翻页），所以行内不该指望滑动手势。原型给的上限是桌面行内 8 枚、超出进「更多 ▾（n）」。
- L3 排序：右上角一枚下拉（`最新上架 / 最高热度 / 最高收藏`），hover 出菜单、点击也可出（不能只绑 hover，触屏当鼠标用是常见场景），键盘 `Tab/方向键` 可遍历 chip（现状 `ChoiceChip` 已可聚焦，焦点顺序见 §6.1.5）。
- 榜单页桌面形态：上方两行「赛道 + 榜单」（不是「赛道 + 周期」，见 §4），下面是竖向位次列表（宽屏不做多列网格，位次必须是一条竖向序号链）。hover 预览卡 1.5s 起、300ms 可关（Netflix 大屏/网页被骂的点就是 hover 预览收不掉）。

**TV**：按焦点行模型（[Android TV 焦点系统](https://developer.android.google.cn/design/ui/tv/guides/styles/focus-system?hl=zh-cn)、[Apple HIG](https://developer.apple.com/cn/design/human-interface-guidelines/remotes)）另做 `tv_ranking_page`，不共用触控滑动模型 —— 逐层的分派已在 **§6.2** 定稿，原型也已画出 TV 视图；实施仍属另案（§9 P3）。

### 6.1 人机交互规格（逐层：触发 → 反馈 → 请求 → 持久化 → 边界）

下面每条都对应原型里可点的一处；「反馈」列同时是本仓 widget 测试的断言面（§10）。措辞按平台×设备族分写，不给一套两边用。

#### 6.1.1 L1 类型（换页，最重的一层）

| 项 | 规格 |
| --- | --- |
| 触发 | 触控：单指点击 chip；桌面：鼠标左键 / 聚焦后 `Enter`/`Space` |
| 即时反馈 | 被点 chip 立刻进入选中态（不换动画时序：桌面 `desktopHost` 零翻页动画，v0.3.13 已落地）；内容区进骨架（§6.1.4 的 loading），**不是**空白 |
| 请求影响 | `select_items.genre = [新类型]`、`req_scene` 随之（真人剧是 `default`，另两型是各自 id，`catalog.dart:477`）；同时把 L2/L2′ 全部归零 |
| 持久化 | 每个类型一份保活记录（现状 `_ThemeFeed` 的键含 genre）；离开再回来不重新拉 |
| 边界 | ① 词表缺行时类型行**照样能点**——类型是唯一不依赖 `selector_rows` 的层（它由前端白名单 `catalog.dart:403-407` 定死）；② 快速连点三次：以最后一次为准，前两次请求丢弃（现状 `RequestBudget` 取消机制）；③ 切换失败：保留旧类型内容与选中态，只顶一条可关提示，不许把用户踩空成空页 |

#### 6.1.2 L2 主题（换这一页内的可滑页）

| 项 | 规格 |
| --- | --- |
| 触发 | 同上；再次点击已选中项 = 取消回「全部」（上游 items 里没有「全部」这一项，是前端补的） |
| 即时反馈 | chip 态变化 + 该主题自己的 feed 换页；已有保活则**秒回**（不重骨架），这是 v0.3.6–0.3.7 已实测的行为 |
| 请求影响 | `select_items.category_dim_theme = [cate_x]`；换主题不换页、不换类型 |
| 持久化 | 键 = `genre|theme`；主题行本身在类型内记住上次选中 |
| 边界 | ① **缺行是常态不是异常**：本次词表没给主题 → 整行不出现（连标签都不画），列表仍按「类型+排序」出内容，行位给一句状态文案 + `现在重试`；② 上游 `selection_type` 若为多选，UI 需允许并配「已选 n」计数（实测主题行是单选，`selection_type=3` 的赛道行也是单选，先按单选实现）；③ 触控族滑动到最右还有 `≡` 与 `排序` 两枚固定控件，它们不随内容一起滑走 |

#### 6.1.3 L2′ 更多筛选（多维抽屉/下拉：只改请求，不换页）

这是本轮新增的一层，承载上游实测的其余维度（各类型项数：主题 8–29、设定 8–42、背景 9–11、受众 2、时间 4，画风 3 与状态 2 只有漫剧有）。

| 项 | 规格 |
| --- | --- |
| 入口形态 | 触控：第二行尾部一枚 `≡`（已选时在角标显数）；桌面：第二行尾部 `≡ 更多筛选 · n`，点开右上角浮层。**两者都不占第一行**——它改的是参数，权重不该和换页同级 |
| 打开后 | 每个维度一个小节，标题用上游 `row_name` 原文（「全部设定」「全部画风」），条目用上游 `show_name` 原文；每项旁边给 id 只对调试可见，正式界面不显示 `cate_*` |
| 选一项 | 立刻发请求、列表就地换；**弹层不收起**（多选式抽屉一次只点一个是常态），收起由用户的 `完成`/`Esc`/点遮罩决定 |
| 「不限」 | 每个维度第一节前置一枚「不限」；点它是清该维，不影响其他维 |
| 完成 | 触控：底部主按钮 `完成（已选 n）`；桌面：右上角浮层同样给 `完成`。收起后第二行尾部 chip 显 `≡ · n` |
| 请求影响 | `select_items` 内对应键从 `[]` 变成 `[id]`；`_selection()` 今天已在发其中 4 个键（空数组），画风/状态两键需补发 |
| 持久化 | 与主题同层：记在 `genre` 的保活记录里，**换类型全部归零**（和现状「换类型重置题材」保持同一条语义，不新增第二套规则） |
| 边界 | ① 维度集合按类型不同：漫剧有画风/状态，真人剧没有 → **缺什么就不画什么，不给空壳小节**，抽屉底部用一行小字说明「本次词表没给：画风、状态」（原型实测：真人剧抽屉 4 节、漫剧 6 节）；② 42 项的设定行在触控族必须可滚（抽屉内纵向滚，行内 chips 换行排布）；③ 词表整体缺席时 `≡` 仍可点开，但里面只有「本次词表没给 + 重试」，不允许出现一个空白抽屉 |

#### 6.1.4 L3 排序（只改请求，位置不动）

| 项 | 规格 |
| --- | --- |
| 触发 | 触控：第二行尾部 `排序 · 最新上架 ▾` → 底部弹层三项；桌面：右上角下拉（hover 120ms 出、离开 300ms 收；点击恒出） |
| 反馈 | 列表内容换，**滚动位置与页面不换**（这条是「排序 ≠ 换页」的可感知证明）；chip 文案回显当前档位 |
| 请求影响 | `select_items.sort = [online_time|hot_score|hot_collect]`；上游没有「推荐」「追剧」两档 |
| 持久化 | 排序属于该 pane 的状态，跟着保活记录存；不改设置页的全局值（现状 `settings.catalogSort` 的语义保留，二者的关系在实施轮定，本轮界面上只呈现一档来源） |
| 边界 | ① 排序换档时如果 feed 正加载中：排队，不并发两次；② 排序失败：档位回滚为上一次成功值，别让用户以为排到了 |

#### 6.1.5 状态、骨架与错误（四个态，原型右上角可切）

| 态 | 什么时候出现 | 画什么 | 不画什么 |
| --- | --- | --- | --- |
| ok | 词表与 feed 都到 | 完整两行 + 网格/位次列表 | — |
| loading | 换类型/换主题/进榜单的第一次取数 | 行骨架（一行灰条）+ 卡骨架（3:4 灰块），保留吸顶带位置不跳动 | 不画转圈圈占满屏、不清空已有内容 |
| 词表缺行 | `selector_rows` 没回（实测 4 次里 1 次全缺、另几次各缺 1–2 型） | 主题行整行不出现；桌面在位置给一句「上游这次没回该类型的 selector_rows —— 列表仍按类型+排序出内容」+ `现在重试`；触控族同一语义压成行内**一枚可按的** chip（`主题词表这次没回 · 重试`），不是一枚 `pointer-events:none` 的死标签 | **不给「暂无数据」空页**（内容其实是有的是的），不画空 chip |
| error | 请求失败/HTTP 非 200 | 顶部一条可关提示 + 保留上一次成功内容；重试按钮 | 不弹全屏错误、不清状态、不自动重试到第三次（现状 `NetworkRetry` 已限次） |

`现在重试` 成功后恢复：上一次的选中值 + 上一次的滚动位置（失败态从不改这两个，所以恢复是免费的；这条要在测试里钉死）。

#### 6.1.6 二次交互：下钻与回跳（本轮新增，原型可点）

| 从哪 | 动作 | 到哪 | 带的参数 | 措辞/边界 |
| --- | --- | --- | --- | --- |
| 发现页卡面（桌面 hover 1.5s / 移动点卡） | `找同题材 ›` | 发现页 L2 | 该剧 `sub_title`/`tagNames` 的首个体裁词写进 `category_dim_theme` | 命中时读出窗显 `cate_x`；**未命中时不硬凑**：只切类型、主题留「全部」，并说明「本类型只有 n 个主题」（实测：漫剧榜上的「恋爱」不在漫剧主题词表里，8 个主题中无此项） |
| 发现页卡面 | `看它所在的榜 ›` | 榜单页 | 赛道=该剧所属域、榜单=热播榜 | 榜的位次来自下标；跳转不换 L1/L2 的选中（它们不在这条请求里） |
| 榜单行 | `找同题材 ›`（行内就地小链接，hover/focus 才出下划线，触控族常驻可见） | 发现页 | 赛道→类型域映射（`comic_series_rank→comic_series`、`human→short_play`、`ai_playlet→ai_series`）+ 该行 `sub_title` 的题材词写进主题 | 演员赛道（剧星榜/星光榜）本轮不接 → 不产生此链接；某赛道这次没返回子榜（实测 live-sample 那次的演员赛道连 `sub_cell_selector` 都没有）→ 该枚赛道 chip 不画 |
| 发现页榜单入口卡 | 卡本体 / `全部榜单 ›` | 榜单页 | 入口卡显示的前三名的热度文案与榜单页必须同源（同一 `rec_text_item`，不能一处 `play_cnt` 一处热度） | 入口卡是目的地切换，不是筛选：点了不改 L1/L2 选中值 |

#### 6.1.7 焦点、手势与计时（逐输入族）

- **桌面焦点顺序**：目的地 rail → L1 类型 → L2 主题 → `更多 ▾` → `≡ 更多筛选` → 右上角排序 → 卡面 → 卡内 `找同题材 ›`。弹层内焦点循环在弹层里，`Esc` 关弹层并把焦点还给触发它的那枚控件（不是还给页面顶部）。
- **键盘键**：`Tab`/`方向键` 在 chip 行内移动（行是原生顺序，不做漫游）；`Enter`/`Space` = 点按；`Esc` 关弹层/hover 预览；本轮新增两枚单键 `F`（开/关更多筛选）、`O`（开/关排序）——与播放页现有快捷键不冲突（实施时要在 `shortcuts.dart` 里对一遍）。
- **hover 预览**：进 1.5s 起、出 300ms 收且可 cancel（鼠标移进预览卡本体则不关）；预览里两个二级动作可点。**不做**：hover 出下拉菜单（除排序那一枚）、hover 自动播放。
- **触控族手势交接**（沿用已发版的三级链路，不改语义）：chip 行横向滑动 → 到边后交给内层 pageView → 再到边交外层 tab；纵向：列表上滑只收顶段（搜索/离线/提示），两行筛选吸顶不动（v0.3.12 实测）。抽屉：上滑展开、下滑或点遮罩收起；抽屉内纵向滚优先于页面滚。
- **计时汇总**：hover 起 1500ms / 收 300ms；排序菜单 hover 出 120ms；骨架不短于 200ms 显示（避免闪烁）；请求换页与排序的等待都用同一套骨架，不给两套动画。

### 6.2 TV（遥控族：D-pad 五向 + 确认 + Back）

原型第三个视图就是这一节的可操作规格（真键盘方向键 = 遥控器方向，`Enter` = 确认，`Backspace`/`Esc` = Back）。它**不共用**触控族的滑动件；契约全部来自本仓已实施的 TV 代码与设计稿：sidebar 焦点即切换与「向右进内容区」见 `packages/app/lib/features/tv/tv_library_page.dart`，题材行/防抖/分页见 `docs/design/tv-topic-pagination.md` 与 `tv_feed_page.dart`，跨行阅读顺序与末行补位见 `docs/design/tv-cross-row-focus-navigation.md` 和 `packages/tv/lib/src/grid.dart`，焦点=描边/选中=底色见 `packages/tv/lib/src/focusable.dart`，大屏字号与 1.03 缩放是 `docs/design/android-tv-adaptation.md §4.3` 的建议起点。

| 层 | TV 落点 | 触发 | 边界与理由 |
| --- | --- | --- | --- |
| L0 目的地 | 左侧 sidebar：发现 / 榜单 / 本地缓存 / 我的 | 焦点即切换、首尾不循环 | 侧栏不放「发现/分类」双页（同一纵向列表里两个同形态入口，会让「路过即切换」付双倍代价）；类型也不留在侧栏——`rank` 不吃 genre，把 榜单 挨着 短剧 摆就是在暗示「这是短剧的榜」 |
| L1 类型 | 内容区第一行焦点行 | **确认键才切换** | 它换页并重置 L2/L2′，「路过即切换」的代价太大；焦点经过时读出窗明说「按焦点不切换」 |
| L2 主题 | 第二行焦点行，行尾再挂 `≡ 更多筛选`、`排序 · X`、`搜索` 三枚 | 焦点即筛选 + 220ms 防抖合并连续按键 | 全部选项常驻构建：TV 折叠成「更多 ▾」是错的（遥控器没有下拉），溢出靠 keep-visible 把焦点项留在视口内 |
| L2′ 更多筛选 | 全屏浮层：左维度列 + 右选项行 | 向右进该维选项行；选完**不收**面板 | 背景 `ExcludeFocus`，焦点走不进被盖住的区域；Back 只关这一层并把焦点还给触发它的那枚控件 |
| L3 排序 | 行尾一枚，点开三档面板 | 上下换档、确认一次即提交 | 只改 `select_items.sort`，不换页、不改滚动位置；TV 这一枚写回设置 → 内容列表 → 全局排序（现状），所以页面上永远只有一个档位来源；长按方向键只是移动焦点，重复/抬起事件不再提交 |
| 榜单 | 赛道行 + 榜块行 + 竖向位次列表 | 赛道**确认键**（会重置榜块）、榜块**焦点即筛选**（只换 feed） | 位次 = `cell_data` 下标；一行只有一个焦点目标，所以行内不做二级小链接；上游无周期维（`inner_rows=0`）→ 不给「日/周/月」；`rec_arrow_type` 四次全 0 → 趋势保持虚线占位 |
| 网格与分页 | `TvGrid`：`maxExtent 190 / aspectRatio .68 / 间隔 14` | 尾部两行焦点即预取；末项按右登记**一个**待续页移动，新增到达后焦点前进一次 | 界面上没有「加载更多」按钮；跨行按阅读顺序（行末向右 = 下一行首），跨行只移动焦点不确认播放；末行不满补位并记住目标列；第 0 项向左回当前选中的 sidebar 项 |
| 详情 | 独立路由浮层 | 主操作区含 `▶ 开始观看`、`下载剧集`、`收藏`、`找同题材 ›`、`看它所在的榜 ›`；下面是剧集格 | TV 没有 hover 预览，二级动作只能落在详情页；剧集第一行按上回主操作区、末行按下到「‹ 返回目录」；「最近浏览的剧集」与「当前播放集」分开保存 |
| Back | 逐层消费 | 详情 / 面板 → 取消在途的待续页移动 → 回当前 sidebar（列表位置与 offset 保留）→ 再按才交系统首页 | 每次只消一层，不无限拦截；详情是独立路由，其边界不调用目录的 sidebar 回调 |

两处与其他族不同、必须在实施时守住的判断：**焦点即筛选只用于「改了什么都不变」的层**（主题、榜块），凡会换页或重置下层的（类型、赛道）一律要确认键；**溢出永不折叠**（42 项的设定行也全部构建）。榜单入口卡在 TV 上不做——sidebar 里 榜单 就在一按之下，触控族补的那层深度在这里不存在。

## 7. 原型 v2（本轮交付物：跑的是实机取样的真词表）

`docs/design/prototypes/discover-filters-ranking.html`，自包含单文件、无网络依赖、离线双击即开。v1 的词表是编的；**v2 里每一个筛选名、每一条赛道、每一块榜、每一个热度数字都来自 `docs/evidence/ranking-fields/`**（脚本把四次取样的并集导出成文件内的 `API` 常量，字段名与 `show_name`/`selector_item_id` 原样保留，页脚标了取样时刻）。

- **顶栏两枚开关**：视图（桌面/移动/TV 遥控族）+ 数据状态（有词表 / 加载中 / 词表缺行 / 请求失败）。后者不是装饰——词表按次缺席是实测出来的（§1 末），缺行态下主题行整行消失、只剩类型与 `≡ 更多筛选`，这就是 §6.1.5 那一条的预览。
- **请求读出窗**：每次点击都把「这一层改的是路由还是哪个参数」打在页面上，参数名用上游原文（`select_items.genre`、`category_dim_theme=[\"cate_6\"]`、`selected_items='comic_series_rank'`、`sub_selected_items='comic_series_hot_play'`、两个接口路径），所以「一层一义」是可验证的而不是口号。读出窗与渲染共用同一个判断函数（`themeRow()`），不会出现画了行却说没画的自相矛盾。
- 发现页：L1 类型（换页）/ L2 主题（页内可滑页）/ L2′ 多维抽屉（真人剧 4 节、漫剧 6 节，缺的维度抽屉里点名）/ L3 排序（三项）四层分离；切类型把 L2/L2′ 全部归零（保住现状语义）；抽屉与下拉里的选项**选完不收弹层**。
- 榜单页：赛道 × 榜单（不是周期），赛道与榜块全部由 `cell_selector` 的数据现算现画（原型这份常量是 live-sample 那次 = 25 块；四次实测 25–27，所以页面上没有一处写死条数），app 未接的 22 块（= 这份常量 25 − 已接 3）点下去给的是「接口已发布、app 未接」状态说明；演员赛道那枚给的是「这次没返回子榜 → 不画空 tab」的说明；位次 1–3 强调、热度/收藏/评分/徽标/占位主色都是真值，只有趋势保持虚线占位并写明「字段位存在、四次全 0」。
- **二次交互**：卡面 hover 1.5s 出预览 → `找同题材 ›`（写进 L2 主题，未命中时明说「不在本类型 n 个主题里」）/ `看它所在的榜 ›`（跳榜单，赛道→类型域有映射）；榜单行内就地 `找同题材 ›` 回跳发现页。发现页榜单入口卡显示前三名的真实热度文案。
- 键盘：`Tab` 顺序、`Esc` 关弹层、`F` 开更多筛选、`O` 开排序（§6.1.7）。**TV 视图下这三枚让位**：方向键 = 遥控器五向、`Enter`/`空格` = 确认、`Backspace`/`Esc` = Back，屏幕下方实时给出 `zone / 焦点项 / 列数 / 页 / 最近按键 / 该次移动改的是哪一层`，所以「焦点即切换 vs 确认键才切」是可当场验证的而不是文档口径。
- 原型只是预览面，不代表实现承诺；`color_dominate` 只当占位主色用，不当封面用。
- **原型的验证口径**：本轮用浏览器加载该文件做了结构断言与交互驱动（切目的地/切类型看主题是否归零/在抽屉里选项看弹层是否留在原地/选排序看读出是否只变参数/点下钻看是否带上了正确的 `cate_*`/切四个数据状态看行是否整行消失），控制台无报错、`node --check` 通过；TV 视图另按 §6.2 逐层驱动过一遍（sidebar 往返、向右恢复最近停留行、类型确认键、主题防抖、进网格跨行、尾部预取不抢焦点、末项按右待续页移动、详情/三种浮层、Back 逐层），并跑了 400 次随机按键 ×（含切数据状态与切视图）的不变量检查：焦点下标不越界、焦点态必须能在 DOM 上画出描边、无异常无控制台报错。**没有像素级结论**——本轮的浏览器截图只用于确认布局没有互相压字，未落成 `docs/evidence/` 取证帧，实施轮仍按 §10 补。

## 8. 后端/上游配合清单（本轮已把「未验证」改成实测结论）

原清单五条，四条已被四次实机取样回答，剩下的都是**产品口径**而不是接口缺口：

1. **榜单带 genre**：**上游其实带了，形式是赛道**。`cell_selector` 发布 5 条赛道（`all/comic_series_rank/human/ai_playlet/ranklist_celebrity`）× 25–27 块榜（四次取样并集 27，单跑 25/26/27/27，条数会抖），`selected_items` 就是类型域的另一种写法 → 不需要新接口，需要 `rank()` 把 `track` 参数化并停止硬编码（`catalog.dart:506-550`）。附带两条实测约束：① 「全部」赛道不是并集，它独占臻果榜/预约榜/追更榜；② 演员赛道的两块是演员榜、条目不是剧，`RankEntry` 不能一律当 `Drama`。
2. **周期与历史榜**：**没有这一维，设计已删**。四次取样 `inner_rows` 全为空数组；「日/周/月」与历史快照（猫眼那种）在现接口上不成立。要做得等上游另发 cell 或赛道，不是前端能凑的。
3. **位次/热度/趋势字段**：**热度、收藏、评分、徽标、副标题、占位主色、更新时刻全部实测存在**（字段名与样本值见证据 README §4），是 `Drama` 模型没留；**位次确实只能靠下标**（无名次字段）；**趋势只有字段位**（`rec_arrow_type` 四次 30 张卡全 0）→ 界面保持虚线占位，抓到语义再接。
4. **更新口径文案**：`rank_version` 给的是整分钟 epoch（实测 1793325600=02:00:00Z、1793325840=02:04:00Z，滞后取样时刻 0–4 分钟），且**推荐榜返回空串**。所以页面能写「更新于 10:04」（非空时），不能写「实时」，也不能在三块榜上统一写「每日更新，统计前一日」——后者是产品承诺，仍需上游确认统计窗口。
5. **口径冲突（新增，必须写进实现约束）**：同一张卡上 `play_cnt`=1035 与 `rec_text_item`=「6182万热度」并存，差四个数量级 → **界面只允许出现一个「热度」，取 `rec_text_item`；`play_cnt` 不得并排显示**。
6. **筛选词表的可用性（新增）**：`landpage/v` 的 `selector_rows` 按次缺席（四次取样：真人剧 2/4、漫剧 2/4、AI 剧 3/4、一次全缺），而同一时刻榜单四次全通。这决定了：① 界面必须有「缺行」分支（§6.1.5）；② 榜模块不能与词表共用一次成功；③ 实施时建议对词表做进程内缓存并在缺行时回落上一次成功值——这是新增的容错要求，现状代码没有。
