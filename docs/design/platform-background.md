# 后台播放、下载与悬浮播放的平台设计

三个独立开关：后台播放、后台下载、悬浮播放；默认关闭，保存后生效。移动端新增开启说明，告知媒体控制、通知、流量和系统调度；后台下载默认仅 Wi-Fi，桌面不套用 Wi-Fi 限制。

| 能力 | Android | iOS | macOS / Windows / Linux |
|---|---|---|---|
| 后台播放 | audio_service 媒体前台服务、媒体通知和耳机控制 | audio 后台模式、AudioSession、锁屏/控制中心 | 进程存活时最小化继续；无移动端前台服务 |
| 后台下载 | 系统 WorkManager 下载和进度通知 | 系统 URLSession 下载，Dart 解密可能需回前台 | 固定应用内 Dio 下载（`background_downloader` 在桌面没有原生实现）；进程退出后不保证继续 |
| 悬浮播放 | API 26+ 系统 PiP，不使用任意应用悬浮窗权限 | 本地 MP4 交给 AVPlayerLayer/PiP，返回同步进度 | 当前窗口缩小并置顶，保存/还原原窗口尺寸、位置、置顶和全屏状态 |

## 交互

设置使用“后台与悬浮播放”分组。移动端首次保存开启状态先显示说明；下载通知授权由系统询问。播放器仅在允许悬浮时显示画中画按钮，手动进入，不因离开页面自动弹窗。

Android 画中画时只渲染视频，隐藏普通页面按钮；iOS 使用系统播放视图，避免将 Flutter texture 冒充原生 PiP 图层。桌面小窗保留播放器控制与退出按钮，退出或关闭播放页时还原窗口。

后台播放继续使用当前本地视频，不另建网络播放源。移动端来电/音频打断或拔出耳机时暂停。关闭后台播放则在窗口隐藏/应用暂停时暂停；inactive 状态（例如权限对话框或短暂失焦）不立即打断。

## 下载与缓存

系统下载只获得视频 URL 和通用 User-Agent，不获得账号 Cookie/Token。所有输出进入私有工作文件；仍通过共享 Dart 解密、MP4 校验和原子发布，才算已缓存。

开启后台下载后，预缓存任务额外持有运行时引用，离开播放页仍可完成已经排队的任务。移动端关闭开关会取消本次进程中的系统任务；已完成文件不删除。等待 Wi-Fi/网络时显示等待状态。桌面不切换传输实现，该开关只决定是否在窗口被遮挡或应用退到后台时继续准备缓存。

待处理记录保存 VID、清晰度、文件名、系统任务 ID 和安全存储引用；内容密钥在系统安全存储。正常处理后清除记录和密钥。启动时恢复已经完成的私有文件，校验后才发布。上个进程遗留且尚未完成的任务取消后清理，后续可重试，不承诺强杀后无限续传。

iOS 后台模式不能当作任意 Dart 常驻执行权限；只让系统继续传输，解密/新片源解析/新任务调度可能延后至返回 App。用户强制结束 App、系统限制、Wi-Fi 不满足均会影响继续执行。
