# v0.3.2 Android TV 验证 — findings

被测：CI 产出的 v0.3.2 TV 发布包（tag v0.3.2 / commit 099f6d5），运行在 `emulator-5554`（1920x1080）。
驱动：`remote.sh`（`adb shell input keyevent` + `exec-out screencap` + `uiautomator dump`）。模拟器允许事件注入，未使用任何桌面合成点击。
证据：本目录 `*.png` + `tree-*.txt`（每步一张截图 + 一份语义树）。语义树脚本 `dump_tree.py` 每次最多输出 15 个带文案节点，**因此"树里没出现某节点"不等于"该节点没焦点"**——本文件所有焦点结论都以 `<FOCUSED>` 行为准。

## 结论速览

| 项 | 结果 |
| --- | --- |
| 详情页操作行合并为一行 | 通过 |
| 选集块限高 + 水平分页（视觉与翻页） | 通过 |

## 通过项

1. **操作行一行化**：`08-detail-top.png` + `tree-23-detail-top.txt` — 「▶ 开始观看」(355x162)、「下载剧集」(250x146)、「♡ 收藏」(209x148) 同一行（y 468–630），收藏已并入行内。
2. **选集块限高、水平分页**：`tree-23` 显示 4 列 × 4 行（格 429x286，块总高约 1144）；页指示器 `episode-pager-page-indicator` = 「第 1/6 页」（86 集 ÷ 16 格/页 = 6 页，与 `rows=4`、宽度推导 4 列一致）。块高在翻页前后恒定，未随集数增长。
3. **翻页确实换页**：`tree-60-after-activate-next.txt` — 指示器「第 2/6 页」，尾行为 29/30/31/32（第 2 页 = 17–32）；`tree-62` 回到「第 1/6 页」，尾行 13–16。
4. **相关推荐**：`tree-27` 起持续可见 — 标题「同题材 · 喜剧」+ 5 张海报（这个律师有点野 / 望父成虫 / 缘来药引是我呀 / 别叫我小孩 / 客官请上座），横向 rail；**无「热度」「最新」角标**。此处走的是同题材分支（王妈题材命中分类名），非「平台热门」兜底。

## 缺陷

### D1 选集格在真机 TV 页面上遥控器不可达

从「开始观看」按 Down（`keyevent 20`）：

- `tree-24-into-pager.txt` … `tree-27-pager-r4.txt`：`<FOCUSED>` 一直是 **推荐位第一张卡「推荐：这个律师有点野」**，不是任何 `第 N 集` 格。四棵树里格子的变化（13–16 出现在 y=112）是外层滚动视图为了把获得焦点的推荐卡带进视野而**自动滚动**的结果，不是焦点进了选集。
- 换路径同样失败：`tree-30-down-from-download.txt`、`tree-43-down-again.txt`、`tree-51-down-to-rail.txt`（从「下载剧集」Down）→ 焦点落在推荐卡「望父成虫」。
- 从下往上能碰到的只有箭头：`tree-55-up-toward-next-arrow.txt` → `<FOCUSED>` = 「下一页」（经 `tree-52→54` 在推荐 rail 里 Right 移动后 Up）。
- 全程 21 棵语义树里，**没有任何一棵的 `<FOCUSED>` 是 `第 N 集` 格**。

即：用户用遥控器进不了选集，选集块在 TV 上等于只能看不能选。组件本身是带焦点节点的（`packages/app/lib/playback/episode_pager.dart:289,300-311` 每格 `TvFocusable(focusNode: _cellNode(global))`），所以这是**页面级焦点遍历顺序/视口过滤**问题，不是格子没接焦点。根因未定位，需要单独排查（候选：外层 `SingleChildScrollView` 与 `PageView`+`GridView` 三层视口的焦点可见性过滤，叠加 `TvNavigation` 的 `ReadingOrderTraversalPolicy` 覆盖方向遍历，见 `packages/tv/lib/src/environment.dart:37-39`）。

### D2 翻页后焦点交接失效，最坏情况焦点彻底丢失

- 「下一页」在中间页翻页后焦点仍停在箭头上：`tree-60`（第 2/6 页，「下一页」`<FOCUSED>`）。代码可解释：`_step()` 只在**边界页**给出 handoff（`episode_pager.dart:201-211`，`handoff` 在非边界为 `null`），与 203-204 行注释「不让光标停在半路」的意图不一致。
- Left 到「上一页」(`tree-61`) 再激活 → `tree-62`、`63`、`64`、`65` **连续四棵树没有任何 `<FOCUSED>` 节点**：页面上再无高亮，且期间按过 Right(`64`)、Down(`65`) 都没有恢复焦点。
- 唯一出路是返回：`tree-66-back-with-lost-focus.txt` 已回到片库网格页。

即：TV 上按「上一页」翻一页，遥控器会失去对页面的控制，用户只能退出详情页。

## 与代理自报的差异（更正）

前一版验证过程把 `tree-24/25/26/27`（命名 into-pager / pager-r2 / r3 / r4）当作「Down 依次进入选集第 1–4 行」，本文件按 `<FOCUSED>` 行逐棵复核后推翻：那四步焦点全在推荐位第一张卡上，D1 因此从「未确认」升级为「确证」。

## 代理留下的夹具：2 条失败如何裁定

`packages/app/test/episode_pager_tv_page_harness_test.dart`（未跟踪、非产品代码，结果见 `harness-episode-pager.log`，`+2 -2`）：

- `real page: the pager arrows are reachable, the cells are not` 失败于 `arrows must be reachable`（第 193 行）。裁定：**夹具假设错误，不是新缺陷**。它只按 Down 连按 8 次找箭头，而真机上箭头是从推荐 rail 用 Up 到达的（`tree-55`）；「格不可达」这一半（第 194 行）与 D1 一致。
- `real page: the arrow hand-off strands the focus` 失败于 `Expected: '第 2/6 页' / Actual: '第 2/3 页'`（第 212 行）。裁定：**夹具算术错误**。夹具用 96 集、1920x2400 测试面，列数按宽度推导为 8 列 → 32 格/页 → 3 页；「6 页」是按真机 4 列布局算的。它真正要断言的「hand-off 落不到 `episode-cell-0`」在第 222 行，因前一断言先红而**未执行**，D2 仍需以真机证据（`tree-62`–`65`）为准。

两条失败都不构成产品缺陷，也都不能反过来为产品开脱。该夹具建议按 D1/D2 修复方向改写（断言「Down 应落到 `episode-cell-0`」为期望行为），或随产品决策一并删除——文件头注释本身写明「产品决策定了就删」。
