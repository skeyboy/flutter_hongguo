# Android 真机 · 真实数据人工操作验证

对齐 TV 那套验证方式：TV 用 adb DPAD + screencap；手机这里用 adb tap/swipe（系统级输入注入）+ screencap，全程跑 **release mobile 包 + 真实上游数据**，不注入任何 fake runtime。

## 环境

- 设备：小米 23113RKC6C（vermeer，Android 16 / API 36），无线 adb transport `adb-8c9cf729-xvKuGK._adb-tls-connect._tcp`（USB transport 会被 HyperOS 静默拒绝安装）
- 包：`flutter build apk --release --flavor mobile --split-per-abi` → `app-arm64-v8a-mobile-release.apk`，`adb install -r -d` 安装
- 输入：`adb shell input swipe x1 y1 x2 y2 duration` / `input tap x y`，屏幕物理 1440×3200；所有坐标按此换算
- 截图：通过 `adb exec-out screencap -p` 现场观察，验证截图不纳入版本库；操作日志见 `../mobile-episode-swipe.log`

## 结论

- 本次改动涉及的**发现/分类/榜单筛选带 sticky 收展**、卡片点击、题材切换、详情页选集与相关推荐，在真实数据 + 系统级人工操作下全部表现正确，与 widget 测试和离线集成测试结论一致。
- 移动端卡片 hover 动效为指针族专属，触摸设备无 hover，不影响移动端行为。
- 唯一未闭环项是真实视频播放：上游「正在获取片源」持续无返回（设备挂 VPN，可能相关），该项属上游数据/网络，不在本次改动范围；离线集成测试已用本地视频验证完整播放链路 5/5 通过。
